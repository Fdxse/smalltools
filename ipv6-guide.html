Address format

An IPv6 address is 128 bits long, written as eight groups of four hex digits separated by colons. That gives about 3.4 × 1038 addresses, compared with about 4.3 billion in IPv4.

2001:0db8:0000:0000:0000:ff00:0042:8329

Writing it shorter

  1. Remove the leading zeros in each group: 0db8 becomes db8, and 0000 becomes 0.
  2. Replace one run of zero groups with ::. It can be used only once in an address, or nobody could tell how many zeros each one stands for.
  3. Standard form (RFC 5952): use lowercase, shorten the longest run of two or more zero groups, and pick the first run if two are equally long.

The address above becomes 2001:db8::ff00:42:8329.

Network and interface parts

As in IPv4, a prefix says how many leading bits name the network: 2001:db8:1:2::5/64 is address ::5 in network 2001:db8:1:2::/64. There are no dotted netmasks in IPv6, only prefix lengths.

BitsTypical partWho sets it
First 48Routing prefixYour provider or registry. Sites commonly get a /48 or /56.
Next 16Subnet IDYou. A /48 holds 65,536 subnets.
Last 64Interface IDThe device or DHCPv6 server.

A normal network is a /64. Automatic address setup depends on it, so use /64 for networks with hosts even though the addresses look wasteful. The interface part is not scarce: one /64 holds about 1.8 × 1019 addresses.

In URLs and DNS

  • Addresses in URLs go inside brackets, because colons also mark the port: http://[2001:db8::1]:8080/.
  • DNS uses AAAA records for IPv6 addresses, where IPv4 uses A. Reverse lookups use ip6.arpa.
  • A link-local address may need a zone saying which network card to use, such as fe80::1%eth0, because every link uses the same range.

A device usually has several addresses on one interface at once: a link-local one, one or more global ones, and maybe a ULA. Which one it sends from is chosen for each connection.

Getting an address

  1. The device gives itself a link-local address and checks that nobody else uses it (duplicate address detection).
  2. It asks for routers on the link. A router answers with a router advertisement holding the network prefix and whether to use DHCPv6.
  3. The device then gets its global address, using one of the methods below. Its default gateway is the router's link-local address.
MethodHow it works
SLAACThe device combines the advertised prefix with an interface ID it makes up itself. No server is needed, and this is why networks are /64.
DHCPv6A server hands out addresses, like DHCP in IPv4. The default gateway still comes from router advertisements, not from DHCPv6. Android has traditionally not supported getting an address this way, so check your devices before relying on it.

Interface IDs and privacy

Older systems built the interface ID from the network card's MAC address (EUI-64: split the MAC in the middle, insert ff:fe, flip one bit). That made a device trackable across networks, so systems now use random stable IDs and short-lived temporary addresses for outgoing connections. Common mistakes

  • Blocking all ICMPv6. It breaks neighbor discovery and router advertisements, and also Path MTU Discovery, which shows up as connections that hang on large transfers.
  • Assuming no NAT means no firewall is needed. Without NAT, global addresses can be reachable directly, so a firewall must decide what gets in. Check that its IPv6 rules match your IPv4 ones.
  • Forgetting IPv6 is already on. Most systems enable it by default and prefer it when it works, so it can be in use on a network that was only planned for IPv4.
  • Storing addresses as text. One address has many valid spellings. Convert to the standard form or to 16 bytes before comparing.

Running both

Most networks run dual stack, with IPv4 and IPv6 side by side. Browsers try both and use whichever connects first, with a head start for IPv6 (Happy Eyeballs). IPv6-only networks reach IPv4 through NAT64 and DNS64 instead. The two protocols cannot talk directly without a translator.
